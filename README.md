# Replan 福岡 — 崩れても立て直せる旅程

福岡市内の旅行プランナーのプロトタイプです（デモ用サンプル）。

> 旅程を作る時点で、屋外の予定ごとに**屋内の代わり（Plan B）**を用意しておく。
> 当日に雨や遅延が起きたら通知して、**ワンタップで切り替え**られる。

- 対象: 福岡市内（天神・博多・中洲・大濠公園・百道浜・太宰府）／国内旅行をする大学生・20代の友人グループ
- スマホ表示が前提（モバイルファースト）。API キー不要。外部データはすべてサンプル／モック
- スポットの営業時間・位置などは**サンプルデータで、不正確な場合があります**（アプリ内にも明記）

## 起動方法

Node.js 20.9 以上（22 で確認）。

npm run dev        # http://localhost:3000 （スマホ幅のブラウザ表示がおすすめ）

## デモシナリオ（触って分かるコア体験）

1. トップ画面の初期値がそのままデモ設定です（**友人・普通の予算・グルメとカフェ・ゆったり・小雨OK・日帰り**）。「旅程をつくる」を押す。
2. 旅程画面で、屋外の予定に「☂️ Plan B：…」が付いていることを確認（ブロックをタップすると詳細・Plan B・Google Maps ボタン）。
3. 「当日モードを試す」へ。画面下の **🧪 デモ操作パネル** を開き、現在時刻を **13:00** にする（プリセットボタン or スライダー）。
4. **「雨が降り出す」** を押す（降水確率・開始時刻も設定可）。→「Plan Bに切り替えますか？」の通知が出る。
5. **「今日の残りの屋外予定をすべて切り替える」**（または「1つだけ切り替える」）。→ 変更前後の差分カードが出る。
6. 続けて試せるもの
   - **電車が◯分遅延**: 余白ブロックが遅れを吸収し、吸収しきれない分だけ後ろの予定が押し出される。間に合わない Optional は「スキップ候補」に（大きく遅らせると出ます。例: 90分を2回）。
   - **このスポットが臨時休業**: 代わりの候補への切り替え or スキップ。
   - 「🔗 共有」でリンクを作り、別タブで開くと同じ旅程が閲覧できる。
   - 「デモをリセット」で元の旅程に戻る。

`npm run demo:e2e` は上記を自動で最後まで通して確認します。

## 機能一覧

| 画面 | 内容 |
| --- | --- |
| **入力** (`/`) | 日程（日帰り / 1泊2日）・同行者・予算帯・興味（複数）・ペース・雨への許容度の **6問** ＋ 任意で「絶対に行きたい場所」（スポット一覧から選択） |
| **旅程** (`/itinerary`) | 日別タイムライン。ブロックにラベル **Must / 標準 / Optional / 余白**。タップで詳細と Plan B。**ドラッグ（⠿）で並べ替え → 時刻を自動で再計算**（詳細の ↑↓ ボタンでも可）。「Google Mapsで開く」。Plan B が見つからない屋外ブロックには**警告** |
| **当日モード** (`/today`) | 「**次にやること**」カード（出発までの残り時間）、雨・臨時休業・スキップ候補の通知バナー、**変更前後の差分表示**、デモ用シミュレーション操作パネル |
| **共有** (`/share?s=…`) | 旅程の状態をエンコードした URL。開いた人は同じ旅程を閲覧できる（共同編集なし）。「自分の旅程として保存」も可 |

データは `localStorage` に保存します（サーバー・DB なし）。

### 旅程生成アルゴリズム（`core/planner.ts`）

LLM は使わず、ルールベースです。

1. **ペース設定**: ゆったり＝1日の開始が遅く・スポットは少なめ（目安3）・滞在 ×1.25・余白 45分×最大3 ／ 普通＝4・30分×2 ／ 詰め込み＝6・滞在 ×0.85・15分×1。
2. **スコアリング**（`scoring.ts`）: 興味一致（主カテゴリ +3.0、タグ +1.2）＋人気度、予算超過の減点、同行者との相性、雨許容度による屋外の減点。同じ日の同カテゴリの連続、混雑時間帯、長すぎる移動は減点。直前と同じエリアは加点。
3. **Must** はエリア単位で日に割り当て（1泊2日）、強く優遇して必ず入れる。定休日などで入れられない場合は警告。
4. **時間を先に進めながら貪欲に配置**。営業時間内に収まること（開店待ちは上限あり）・移動時間・日の終了時刻を守る。昼・夜の**食事枠**を確保し、夜景は日没後（17:30〜）に置く。
5. **移動時間**は直線距離×1.3 を道のりとみなし、1km以下は徒歩（4.5km/h）、それ以外は公共交通（待ち10分＋27km/h）で概算（`core/geo.ts`）。
6. **余白**ブロックを間隔を空けて挿入。待ち時間が長いときも余白になる。
7. Must 以外のスポットのうち、スコア下位 1/3 を **Optional** にする。

> ラベルは Must / Optional / 余白 に加えて **「標準」** を追加しています。Must 以外がすべて Optional になると「余力があれば」の意味が薄れるためです。

### Plan B（`core/planb.ts`）

屋外・半屋外のブロックごとに、次の条件で選びます。

- **屋内**であること
- 元のスポットから**2km以内**（直線距離）
- ブロックの**開始時刻にそのまま入れる**（営業時間内）
- **興味カテゴリが近い**こと（カテゴリ近接度 0.3 以上。ユーザーの興味に合えば加点）

旅程内の他のスポット・他ブロックの Plan B とは重複させません。見つからなければ `planB: null` にして警告を出します。時刻が変わると Plan B が使えなくなることがあるため、並べ替え・遅延・休業のたびに付け直します（有効なものは維持）。

### 再計算（`core/schedule.ts`）

- 開始済みのブロックは固定。各ブロックの開始 = `max(前の場所からの到着, 計画上の開始, 遅延による下限)`。
- **遅延**は最初の未開始ブロックに加算。**余白ブロックが先に縮んで**（最短10分）吸収し、吸収しきれない分だけ後ろへ押し出される。
- 営業時間外・終了予定時刻の超過は検出。**間に合わない Optional → スキップ候補**。間に合わない／終了予定を30分超えて遅れる標準・Must がある場合は、手前の Optional を飛ばして改善するかを試算して候補にする。
- 並べ替えは先頭から時刻を詰め直す。スキップ・休業は時間を消費しない。

### 当日モードの雨の判定

雨への許容度ごとの通知しきい値（降水確率）: **屋外NG 30%** ／ **小雨ならOK 60%** ／ **気にしない 通知なし**（手動の切り替えは常に可能）。屋外ブロックは常に対象、半屋外は「屋外NG」のときだけ対象です。

## 本物の API に差し替える場所

| 対象 | 差し替え先 | 実装する interface | 候補 |
| --- | --- | --- | --- |
| スポット | `src/adapters/index.ts` の `adapters.spots` | `SpotProvider.listSpots()` | Google Places API (New)。`setting`（屋内/屋外）・`stayMin`・`crowded` は Places に無いので、種別からの推定や別データが必要 |
| 天気 | `adapters.weather` | `WeatherProvider.getHourlyForecast(date, location)`（時間別の降水確率 0–100） | Open-Meteo / 気象庁 など |
| 移動時間 | `adapters.transit` | `TransitProvider.createEstimator(points)`（2点間を同期で引ける関数を返す） | Google Routes API の行列計算を事前取得して引く |
| 遅延・臨時休業 | 今は `app/today/page.tsx` のシミュレーション操作から `applyDelay` / `markSpotClosed` を呼んでいる | 運行情報・Places の営業状態を検知したら同じ関数を呼ぶ | |
| 旅程生成 | `src/generator.ts` の `generate` | `ItineraryGenerator`（`GenerateInput → Itinerary`） | LLM など（非同期化する場合は呼び出し側 `app/page.tsx` を `await` に） |
| 保存 | `src/store/tripStore.ts` | | サーバー保存にする場合 |

アプリ本体（UI・`core/`）は外部 API を直接呼ばず、`adapters/types.ts` の interface だけに依存しています。

## テスト

`npm test`（Vitest、66件）。主な内容:

- 営業時間外・定休日のスポットが旅程に入らない（土曜・月曜、複数の入力条件）
- Plan B が**屋内・2km以内・その時間帯に営業**している／重複しない／見つからなければ `null`
- 遅延したときに時刻が正しく再計算される（余白による吸収・押し出し・累積・開始済みは固定・スキップ候補）
- 並べ替え、Plan B 切替・元に戻す、臨時休業、差分、次にやること、雨の通知条件、共有 URL の往復
- **デモ設定の旅程に、13時以降の屋外ブロックと Plan B が含まれる**（デモが成立すること）

## 前提・制限

- 旅行日は「直近の土曜（と日曜）」で固定です（質問を6つ以内にするため日付入力は省略）。生成関数は `startDate` を受け取れます。
- 1日目は博多駅から、2日目は宿泊先（天神）から出発する前提です。宿泊先や帰路の移動は扱いません。
- 共有リンクは旅程の内容を URL に含めます（スポットは id のみ）。受け取り側も同じスポットデータを持っている前提です。
- 当日モードの「現在時刻」はデモ用に操作します。実時刻・位置情報には連動しません。
- やらないこと: ログイン・決済・予約、自前の地図表示・ナビ（Google Maps へのリンクで代用）、LLM 連携。
