# Replan 福岡 — 崩れても立て直せる旅程

福岡市内の旅行プランナーのプロトタイプです（デモ用サンプル）。

> 旅程を作る時点で、屋外の予定ごとに**屋内の代わり（Plan B）**を用意しておく。
> 当日に雨や遅延が起きたら通知して、**ワンタップで切り替え**られる。

- 対象: 福岡市内（天神・博多・中洲・大濠公園・百道浜・太宰府）／国内旅行をする大学生・20代の友人グループ
- スマホ表示が前提（モバイルファースト）。API キー不要。外部データはすべてサンプル／モック
- スポットの営業時間・位置などは**サンプルデータで、不正確な場合があります**（アプリ内にも明記）

## 起動方法

## デモシナリオ（触って分かるコア体験）

1. トップ画面の初期値がそのままデモ設定です（**友人・普通の予算・グルメとカフェ・ゆったり・小雨OK・日帰り**）。「旅程をつくる」を押す。
2. 旅程画面で、屋外の予定に「☂️ Plan B：…」が付いていることを確認（ブロックをタップすると詳細・Plan B・Google Maps ボタン）。
3. 「当日モードを試す」へ。画面下の **🧪 デモ操作パネル** を開き、現在時刻を **13:00** にする（プリセットボタン or スライダー）。
4. **「雨が降り出す」** を押す（降水確率・開始時刻も設定可）。→「Plan Bに切り替えますか？」の通知が出る。
5. **「今日の残りの屋外予定をすべて切り替える」**（または「1つだけ切り替える」）。→ **組み直し案**（変更前との差分つき）が出るので、**「この内容で確定」** で反映する。
6. 続けて試せるもの
   - **電車が◯分遅延**: 余白ブロックが遅れを吸収し、吸収しきれない分だけ後ろの予定が押し出される。時間が足りなければ優先度の低い予定から削る案が出る。
   - **このスポットが臨時休業**: 代わりの候補への切り替え or スキップ。
   - 「🔗 共有」でリンクを作り、別タブで開くと同じ旅程が閲覧できる。
   - 「デモをリセット」で元の旅程に戻る。

### デモシナリオB: 固定時刻（帰りの最終便）と「疲れた」

1. トップ画面で **Must に「太宰府天満宮」「九州国立博物館」** を選び（興味に「歴史・文化」を足し、ペースを「普通」に）、旅程をつくる。
2. 旅程画面の **「🔒 固定時刻」→「＋ 追加」→「最終便の例から選ぶ」→「太宰府駅 18:05 の電車（最終）」** を登録（組み直し案を確認して確定）。固定ブロックは鍵つきで動かせず、「17:41 までに『観世音寺』を出発（移動14分＋余裕10分）」と逆算される。
3. 当日モードで現在時刻を **15:00** にし、**電車が30分遅延** → Optional が削られ、最終便に間に合う組み直し案が出る → 確定。「次にやること」カードに「17:41 までにここを出ないと、太宰府駅 18:05 の電車に間に合いません」が出る。
4. **「😮‍💨 疲れた」→「かなり疲れた」** → 60分の休憩が入り、残りの歩行距離が減り（例: 1.9km → 0.5km）、それでも最終便に間に合う案が出る → 確定。
5. 現在時刻を出発すべき時刻の25分前・5分前にすると、**30分前・10分前の通知バナー**が出る。
6. 旅程画面で「固定時刻 → 追加 → 対象に **Cさんだけ** → 自分で入力 → 17:00」を登録すると、グループの予定はそのままで、Cさんが抜けたあとの予定が **「Cさん不在」** になる。

`npm run demo:e2e` は A・B を自動で最後まで通して確認します。

### 旅程生成アルゴリズム（`core/planner.ts`）

LLM は使わず、ルールベースです。

1. **ペース設定**: ゆったり＝1日の開始が遅く・スポットは少なめ（目安3）・滞在 ×1.25・余白 45分×最大3 ／ 普通＝4・30分×2 ／ 詰め込み＝6・滞在 ×0.85・15分×1。
2. **スコアリング**（`scoring.ts`）: 興味一致（主カテゴリ +3.0、タグ +1.2）＋人気度、予算超過の減点、同行者との相性、雨許容度による屋外の減点。同じ日の同カテゴリの連続、混雑時間帯、長すぎる移動は減点。直前と同じエリアは加点。
3. **Must** はエリア単位で日に割り当て（1泊2日）、強く優遇して必ず入れる。定休日などで入れられない場合は警告。
4. **時間を先に進めながら貪欲に配置**。営業時間内に収まること（開店待ちは上限あり）・移動時間・日の終了時刻を守る。昼・夜の**食事枠**を確保し、夜景は日没後（17:30〜）に置く。
5. **移動時間**は直線距離×1.3 を道のりとみなし、1km以下は徒歩（4.5km/h）、それ以外は公共交通（待ち10分＋27km/h）で概算（`core/geo.ts`）。
6. **余白**ブロックを間隔を空けて挿入。待ち時間が長いときも余白になる。
7. Must 以外のスポットのうち、スコア下位 1/3 を **Optional** にする。

> ラベルは Must / Optional / 余白 に加えて **「標準」** を追加しています。Must 以外がすべて Optional になると「余力があれば」の意味が薄れるためです。

### Plan B（`core/planb.ts`）

屋外・半屋外のブロックごとに、次の条件で選びます。

- **屋内**であること
- 元のスポットから**2km以内**（直線距離）
- ブロックの**開始時刻にそのまま入れる**（営業時間内）
- **興味カテゴリが近い**こと（カテゴリ近接度 0.3 以上。ユーザーの興味に合えば加点）

旅程内の他のスポット・他ブロックの Plan B とは重複させません。見つからなければ `planB: null` にして警告を出します。時刻が変わると Plan B が使えなくなることがあるため、並べ替え・遅延・休業のたびに付け直します（有効なものは維持）。

### 再計算（`core/schedule.ts`）

- 開始済みのブロックは固定。各ブロックの開始 = `max(前の場所からの到着, 計画上の開始, 遅延による下限)`。
- **遅延**は最初の未開始ブロックの開始に加算。**余白ブロックが先に縮んで**（最短10分）吸収し、吸収しきれない分だけ後ろへ押し出される。
- **固定時刻ブロックの開始は固定時刻そのもの**。手前のブロックには、固定時刻から逆算した「最遅の開始時刻」を持たせ、計画上の開始より前倒しでも動く（間に合わなければ `fixed-missed` と不足分を記録）。
- 営業時間外・終了予定時刻の超過を検出。並べ替えは先頭から時刻を詰め直す。スキップ・休業は時間を消費しない。

### 再計画エンジン（`core/replan.ts`）

雨（Plan B 切替）・遅延・臨時休業・疲れた・固定時刻の追加などを、**1つの関数 `replan(旅程, イベント, ctx, {dayIndex, nowMin})`** で扱います。結果は「提案」で、元の旅程は変えません。UI は**変更前との差分を見せ、確定ボタンで初めて反映**します（余裕時間の変更・固定時刻を外すだけの場合は、問題が出なければそのまま反映）。

**組み直しの優先順位（高い順）**: 固定時刻 ＞ Must ＞ 休憩・余白 ＞ Optional

**時間が足りないときは、次の順で削る**（違反が解消するまで）。

1. **Optional を後ろから削除**（違反に近い後ろ側のものから。削っても改善しないものは削らない）
2. **各スポットの滞在時間を短縮**（最低滞在時間まで。最低滞在 = スポット標準滞在の半分、15分未満にはしない）
3. **標準の予定を後ろから削除**
4. それでも足りなければ **Must は「削る候補」として提示するだけ**（勝手に削らない）。ユーザーが選んだ Must だけを外して組み直し直す

解釈した点:

- 「標準」（Must でも Optional でもない予定）は、優先順位にないので **Optional と Must の中間**として扱います。
- 余白は従来どおり遅れの吸収材として先に縮みます。「疲れた」で入れた**休憩は保護**され、Optional より先に削られたり短縮されたりしません。
- 最終便に乗ったらその日の予定は終わりなので、最終便のあとの予定は実施不可として扱います（Optional・標準は削除案、Must は削除候補）。

### 固定時刻（`core/fixed.ts`）

- 種類: 帰りの交通（終電・最終バス）／宿のチェックイン／予約（飲食店・体験）／レンタカー返却／集合。
- **出発すべき時刻 = 固定時刻 − 移動時間 − 余裕時間**（余裕時間の初期値は10分。画面で変更でき、変えると再計画される）。各固定ブロックに表示され、当日モードの「次にやること」カードに直近の固定時刻までの逆算が出ます。
- 出発すべき時刻の **30分前・10分前**（過ぎたら「過ぎています」）に通知バナー。
- 固定ブロックは鍵アイコン付きで**ドラッグできず**、固定時刻をまたぐ並べ替えも拒否します。
- **メンバー限定の固定時刻**（例:「Cさんだけ 20:30 の電車」）: グループの旅程は動かさず、「ブロックが終わってから固定時刻の場所へ 移動＋余裕 で間に合う最後のブロック」までCさんが参加し、それ以降を **「Cさん不在」** と表示します。メンバーの名前は旅程画面で編集できます（初期値は同行者から: 友人＝A・B・Cさん）。
- サンプルの最終便（選ぶだけで登録）: 太宰府駅 18:05 の電車／太宰府天満宮前 19:20 の最終バス／筑前前原駅 20:10 の電車（糸島）。**実在の時刻表ではありません**（画面にも明記。デモ用に時刻を決めています）。

### 「疲れた」ボタンと歩行距離（`core/replan.ts` / `core/walking.ts`）

- **少し休みたい**: 次の予定の前に、近く（800m以内）の屋内カフェなどで**30分**の休憩を挟む。見つからなければ場所を決めない休憩にする。
- **かなり疲れた**: **60分**の休憩（500m以内）を挟み、残りの Optional をスキップし、残りのスポットを**移動距離が短くなる順（近い順）に並べ直し**、以降は徒歩を短く見積もる（600m超は公共交通）。**徒歩20分以上かかる移動には、公共交通・タクシーを提案**。
- どちらも **Must と固定時刻は守り**、組み直し案を見て確定します。
- **推定歩行距離**: 徒歩の移動＋滞在中の歩行（屋外の散策は多く、飲食・カフェはほぼ歩かない）を累計して表示。ペースごとの目安は **ゆったり5km／普通8km／詰め込み12km**。「次の予定まで行くと目安を超える」見込みのとき、**「次の予定の前に休憩を入れますか？」**と提案します。
- **グループで使うとき**: 誰でも押せます。押した人の名前は表示せず、グループには「**メンバーの1人が休憩を希望しています**」とだけ出します（操作者を記録・表示する仕組みがありません）。
  ※ この試作は1台のブラウザで動くので、実際の複数端末への通知は含みません。

### 当日モードの雨の判定

雨への許容度ごとの通知しきい値（降水確率）: **屋外NG 30%** ／ **小雨ならOK 60%** ／ **気にしない 通知なし**（手動の切り替えは常に可能）。屋外ブロックは常に対象、半屋外は「屋外NG」のときだけ対象です。

## 本物の API に差し替える場所

| 対象 | 差し替え先 | 実装する interface | 候補 |
| --- | --- | --- | --- |
| スポット | `src/adapters/index.ts` の `adapters.spots` | `SpotProvider.listSpots()` | Google Places API (New)。`setting`（屋内/屋外）・`stayMin`・`crowded` は Places に無いので、種別からの推定や別データが必要 |
| 天気 | `adapters.weather` | `WeatherProvider.getHourlyForecast(date, location)`（時間別の降水確率 0–100） | Open-Meteo / 気象庁 など |
| 移動時間 | `adapters.transit` | `TransitProvider.createEstimator(points)`（2点間を同期で引ける関数を返す） | Google Routes API の行列計算を事前取得して引く |
| 遅延・臨時休業 | 今は `app/today/page.tsx` のシミュレーション操作から `replan()` に `delay` / `closure` イベントを渡している | 運行情報・Places の営業状態を検知したら同じイベントを渡す | |
| 旅程生成 | `src/generator.ts` の `generate` | `ItineraryGenerator`（`GenerateInput → Itinerary`） | LLM など（非同期化する場合は呼び出し側 `app/page.tsx` を `await` に） |
| 保存 | `src/store/tripStore.ts` | | サーバー保存にする場合 |

アプリ本体（UI・`core/`）は外部 API を直接呼ばず、`adapters/types.ts` の interface だけに依存しています。

## テスト

`npm test`（Vitest、117件）。主な内容:

- 営業時間外・定休日のスポットが旅程に入らない（土曜・月曜、複数の入力条件）
- Plan B が**屋内・2km以内・その時間帯に営業**している／重複しない／見つからなければ `null`
- 遅延したときに時刻が正しく再計算される（余白による吸収・押し出し・累積・開始済みは固定）
- **再計画エンジン**: 遅延・休憩（少し／かなり）を重ねても固定時刻に間に合う／時間が足りないとき **Optional → 滞在短縮 → 標準 → Must 削除候補** の順に処理される／**Must は確認なしに削除されない**（ユーザーが選んだ Must だけが削られる）／提案は確定するまで元の旅程を変えない
- **固定時刻**: 出発すべき時刻 = 固定時刻 − 移動 − 余裕（余裕は設定可）／固定ブロックは動かせない／30分前・10分前の通知／サンプルの最終便
- **メンバー限定の固定時刻**で、そのメンバーが抜けたあとの予定が「不在」になり、グループの旅程は変わらない
- **「疲れた」**: 少し＝30分の休憩を近くの屋内カフェで／かなり＝60分の休憩・Optional 削除・近い順の並べ替えで**残りの総歩行距離が減る**／Must と固定時刻は守る／名前を出さない表示
- 歩行距離の累計とペース別の目安（5/8/12km）、休憩の提案
- 並べ替え、Plan B 切替・元に戻す、臨時休業、差分、次にやること、雨の通知条件、共有 URL の往復（固定時刻・メンバーを含む）
- **デモ設定の旅程に、13時以降の屋外ブロックと Plan B が含まれる**（デモが成立すること）

## 前提・制限

- 旅行日は「直近の土曜（と日曜）」で固定です（質問を6つ以内にするため日付入力は省略）。生成関数は `startDate` を受け取れます。
- 1日目は博多駅から、2日目は宿泊先（天神）から出発する前提です。宿泊先や帰路の移動は扱いません。
- 共有リンクは旅程の内容を URL に含めます（スポットは id のみ）。受け取り側も同じスポットデータを持っている前提です。
- 当日モードの「現在時刻」はデモ用に操作します。実時刻・位置情報には連動しません。
- 固定時刻の場所は、駅・空港の例とスポットから選べます（糸島のスポットデータは含みません。最終便の例だけ）。
